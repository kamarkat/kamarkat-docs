> Declare the key in git. Supply the value with `kakt`. Values never enter git.

An app's own secrets — a third-party API key, say — are declared in its `values.yaml` and supplied per environment. Platform credentials such as database passwords are generated for you and never declared here.

## Step 1: Declare it

```yaml environments/dev/shop/values.yaml
secrets:
  - name: PAYMENTS_API_KEY
    capability: "the payment provider the BFF charges cards through"
    workloads: [bff]
```

Commit the declaration. Each secret names the workloads that read it: one missing key stops every container in those workloads.

## Step 2: Supply the value

From the root of your GitOps repository. The tenant and cluster are read from the app's `values.yaml`.

**One key:**

```bash
kakt app secrets set dev shop PAYMENTS_API_KEY
```

It prompts with echo disabled, or reads `--stdin` so a password manager can pipe into it. No flag takes the value, so it never reaches your shell history.

**Several keys:**

```bash
kakt app secrets template dev shop > shop.env      # the declared keys, no values
# fill in shop.env
kakt app secrets import dev shop --from-env shop.env             # lists what it would write
kakt app secrets import dev shop --from-env shop.env --confirm   # writes them
rm shop.env
```

Only declared keys are written, and an empty entry is never written, so a half-filled file cannot blank a value you already supplied.

<Warning>
The file holds your secrets in plaintext. Keep it outside the repository and delete it once the values are in.
</Warning>

## Step 3: Check

```bash
kakt app secrets status dev shop
```

See [Check an app's secrets](/guides/secrets/check-secrets).

<Note>
Secrets are per environment and per cluster. A new environment, or an app moved to another cluster, starts with none, and nothing is copied.
</Note>
