An application is declared in your GitOps repository, one directory per application per environment:

```text
environments/<env>/<app>/
├── values.yaml           what the app is: tenant, app, cluster, hosts, capabilities
├── frontend/Chart.yaml   one directory per workload, naming its chart version
└── bff/Chart.yaml
```

The platform reconciles every `environments/*/*/values.yaml`, so the file existing is what makes the app real.

## Step 1: Create the app's values file

Declare it, then fill it in:

```bash
kakt tenant add-app \
  --env dev \
  --app shop \
  --cluster acme-01 \
  --owner-email platform@acme.example
```

This writes the file below from the template your repository keeps, with the
tenant, app, environment and cluster already filled in. It refuses a cluster your
box has not declared, or one that does not serve `dev`, before writing anything —
so a name that would have generated nothing is caught here rather than at your
first secret.

```yaml environments/dev/shop/values.yaml
tenantId: acme          # the tenant that owns the box, the same in every app
appId: shop             # this product; it gets namespace tenant-acme-shop
clusterName: acme-01    # the managed cluster it runs on

public:
  hosts:
    - shop.dev.acme.example

database:
  enabled: true         # an empty database and a role, owned by this app

resourceQuota:
  cpu: "1000m"
  memory: "2Gi"
  storage: "10Gi"
  pods: "5"

ownerEmail: platform@acme.example

config: {}              # non-secret values your workloads read
secrets: []             # secrets you supply; see "Supply your secrets"
```

| Field | Meaning |
| :- | :- |
| `tenantId` | Your tenant. The same value in every app's file. |
| `appId` | The product, and its isolation unit. It never defaults to `tenantId`. |
| `clusterName` | The managed cluster this app runs on. It must name a cluster your box declares, serving this directory's environment, or nothing is generated for the app. |
| `public.hosts` | Public hostnames. An empty list publishes nothing. |
| `database.enabled` | Provisions the app's own database and role. |

## Step 2: Add a directory per workload

Each workload directory holds one chart dependency. Pass `--workload` once per
workload when you declare the app, or add one later:

```bash
kakt tenant add-app --env dev --app shop --cluster acme-01 \
  --owner-email platform@acme.example \
  --workload frontend --workload bff
```

```yaml environments/dev/shop/frontend/Chart.yaml
apiVersion: v2
name: frontend
type: application
version: 1.0.0
dependencies:
  - name: frontend
    repository: oci://ghcr.io/acme-inc/charts
    version: 0.0.1-rc.awaiting-ci
```

The placeholder version cannot resolve, on purpose. An empty dependency list would render nothing and report healthy, hiding a workload that never deployed. Your app's first build replaces it.

## Step 3: Publish the hostnames and commit

Your managed cluster has one shared gateway whose listeners come from every app's `public.hosts`. Regenerate it, then commit:

```bash
kakt app hosts aggregate
git add environments registry
git commit -m "Declare shop"
git push
```

A preflight check fails review if the aggregate does not match the declarations, so a forgotten step cannot become a hostname that never resolves.
