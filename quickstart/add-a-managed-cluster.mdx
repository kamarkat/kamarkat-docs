Your management cluster runs the platform's services, not your apps. Apps run on a managed cluster, and a new box declares none, so declare your first one now. It is a commit, not another Day-0: the management cluster provisions it.

## Step 1: Declare the cluster

From the root of your GitOps repository:

```bash
kakt tenant add-cluster --name acme-01 --environment dev
```

| Flag | Meaning |
| :- | :- |
| `--name` | The cluster's name for its whole life. Your apps name it to run on it. |
| `--environment` | The stage it serves. An app in `environments/dev/` must run on a cluster that serves `dev`. |

Everything else — your tenant, your management cluster, your repository, the platform version it is declared at, the provider and the region — is already in your repository's box declaration, and is read from there. The command prints each value it read:

```
Read from this box's declaration:
  --mgmt-cluster       acme-mgmt-1794447136
  --tenant             acme
  --provider           hetzner
  --region             fsn1
  --bundle-version     0.3.40
  --gitops-repo-url    https://github.com/acme-inc/acme-gitops-1794447136
```

Pass one of those flags only when you mean to override what your box says. The full list is in the [CLI reference](/cli/boxes-and-clusters#kakt-tenant-add-cluster).

<Note>
A managed cluster is a new set of nodes in your cloud account. On `hetzner` it starts with 2 worker nodes unless you pass `--workers`.
</Note>

## Step 2: Commit

```bash
git add registry && git commit -m "Declare acme-01" && git push
```

The management cluster provisions the cluster from this commit, then installs the platform on it.

## Step 3: Verify

```bash
kakt verify --cluster acme-01
```

It waits for the cluster to converge and reports anything outstanding. For a further cluster later, see [Add a managed cluster](/guides/clusters/add-a-managed-cluster).

<Note>
  **You supply no secrets for a managed cluster.** The management cluster gives it its
  own identity in the box's secret store, which can read only that cluster's secrets and
  issue only that cluster's certificates. The credentials it needs are generated or
  copied there, and its monitoring, alert rules and alert delivery are configured as
  part of creating it. Its database backups go to your box's bucket, in your box's region. The alert destinations you
  gave once at `kakt box init` stay with the management cluster; a managed cluster
  emails its own alerts and is watched by the hub.
</Note>
