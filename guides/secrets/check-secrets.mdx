title: "Check an app's secrets"
description: "List which declared secrets are present and which are missing, by name, never by value."
keywords: ["secrets status", "missing secret", "kakt app secrets status", "template"]
---

> `status` joins what the app declares against what you supplied, and prints names only.

## See what is missing

```bash
kakt app secrets status dev shop
```

A declared secret that is absent is listed with the capability it serves and the workloads it stops, because secrets reach a workload as one object: one missing key withholds the rest with it. The output carries names and never values, so you can paste it into a ticket.

It exits non-zero when anything declared is absent, so a pipeline can gate on it.

## Get the list of keys to fill in

```bash
kakt app secrets template dev shop > shop.env
```

One empty entry per declared secret, each commented with the capability it serves. Run it again whenever the app's `secrets` list changes.

## A workload is not starting

Every declared secret is checked before an app's workloads start. If `status` reports a key missing, supply it: see [Supply secrets](/guides/secrets/supply-secrets). The workload starts once the value is delivered.
