Kamarkat is an agentic cloud-native platform OS for businesses. It brings the infrastructure, application services and agent runtime your product needs together in one integrated platform, and you install it with one executable, `kakt`, in your own cloud account.

One installer. One tested platform. Your infrastructure, credentials and data remain yours.

Kamarkat is built for startups and engineering teams that want a production-capable cloud foundation without assembling and maintaining an internal platform from scratch, and without hiring a platform team to run it.

<Info>
**Where it runs:** Hetzner Cloud (`hetzner`). A box created as `hybrid` can also run worker nodes on your own machines. See [Supported topology](/introduction/architecture#supported-topology).
</Info>

## From download to running platform

<Steps>
  <Step title="Download">
    Get the `kakt` executable. It carries the platform version your box starts on.
  </Step>
  <Step title="Connect">
    Authorize your cloud and git accounts. `kakt` asks for each credential in turn and opens the page that issues it.
  </Step>
  <Step title="Initialize">
    `kakt` creates your GitOps repository and declares your management cluster, and your own CI builds it. The platform comes up in your cloud account.
  </Step>
  <Step title="Build">
    Declare your clusters, applications and agents. The platform provisions them with routing, login, database, secrets and isolation already wired.
  </Step>
</Steps>

`kakt` leads the installation, but it is not a single command: you run a few `kakt` commands, commit once, and start the Day-0 build, which runs for a few hours. [How Kamarkat works](/introduction/approach) explains what each step does, and [Get started](/quickstart/overview) walks through them.

| You provide | The platform supplies |
| :- | :- |
| A cloud account, and the authorization to build in it | Infrastructure provisioning and cluster lifecycle |
| A git organization, and the authorization to write to it | The GitOps foundation every change goes through |
| A domain, and the configuration only you can choose | Networking, DNS, certificates and the gateway |
| Your application code and your business data | Standardized delivery, and the capabilities you select |
| Your operational and release decisions | Versioned platform components, pre-flight checks on upgrades, and the `kakt` CLI |

## Why Kamarkat

| | Traditional vendor-hosted PaaS | Assembling it yourself | Kamarkat |
| :- | :- | :- | :- |
| **Where it typically runs** | The vendor's infrastructure | Your cloud account | Your cloud account |
| **Who typically holds the credentials** | The vendor | You | You |
| **Integration work** | Done by the vendor | Yours, per component | Done before you install |
| **How changes arrive** | The vendor applies them | You track each component | One tested version, proposed to your repository for you to merge |
| **What it is built from** | The vendor's stack | Whatever you choose | Open-source components you can inspect |
| **How you set it up** | Sign up | Many tools, each configured by hand | One CLI |

The first two columns describe representative operating models, not every product in those categories. Some hosted platforms offer deployment into your own cloud or customer-held credentials.

## What arrives integrated

| | |
|---|---|
| **Cluster lifecycle** | Declare a cluster and the platform provisions it, brings up its networking, storage and delivery, registers it, scales it and removes it |
| **GitOps delivery** | Your repository is the desired state; platform controllers reconcile to it |
| **Databases** | A database per application, with credentials, backups and recovery procedures. *Selectable, on by default* |
| **Identity** | An identity provider in your box, and a gateway that fronts your applications with login |
| **Secrets** | A secret store, delivery into workloads, and recovery material held outside the box |
| **Networking, DNS, certificates** | Gateway routing, network policy, DNS records, certificates issued and renewed |
| **Observability** | Metrics, logs, dashboards and alert routing across the box. *Selectable, on by default* |
| **Agentic operations** | A runtime for your agents: isolated sandboxes on your managed clusters, workspaces that persist between turns, and governed collaboration between agents. Engineers and agents operate the platform through the same contracts |

Packaging these would be a distribution. **Pre-integrating them is the product:** the gateway knows about your identity provider, an application's chart gets its database and its secrets, a new cluster arrives with its networking and delivery already configured, and one version moves them together.

## The platform at a glance

Architecturally, Kamarkat is a platform OS: three layers of one product, not three things to buy.

```text
┌─ Agentic operations ──────────────────────────────────────────────────┐
│  Agent runtime · Sandboxes · Workspaces · Agent collaboration         │
│  Engineers and agents, working through the same contracts             │
└───────────────────────────────────────────────────────────────────────┘
┌─ Integrated cloud-native platform OS ─────────────────────────────────┐
│  GitOps · Identity · Secrets · Databases · Gateway · Networking       │
│  Observability · Application delivery · Cluster lifecycle             │
│  Versioned together, reconciled from your repository                  │
└───────────────────────────────────────────────────────────────────────┘
┌─ Business-owned infrastructure ───────────────────────────────────────┐
│  Management cluster · Managed clusters · Cloud infrastructure         │
│  Storage · Networking                                                 │
└───────────────────────────────────────────────────────────────────────┘
```

The agentic layer does not sit beside the platform with its own view of the world. Agents run on your managed clusters, read the same platform state engineers do, and change desired state only through the declarations the platform reconciles. [Agentic operations](/documentation/agentic/overview) describes the runtime.
