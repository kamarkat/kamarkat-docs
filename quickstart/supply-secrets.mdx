title: "Supply your secrets"
description: "Declare every secret your app reads in git, then supply each value once. The value never enters your repository."

Three kinds of value reach a workload, separated by who owns the value.

| Kind | Where it lives | Example |
| :- | :- | :- |
| **Platform credentials** | Generated and delivered for you. You declare the capability, never the key. | Database password, login client secret |
| **Configuration** | `config` in your app's `values.yaml` | Model names, bucket names, base URLs |
| **Your secrets** | Declared under `secrets`, supplied with `kakt` | A third-party API key |

## Step 1: Declare your secrets

Each declared secret names the capability it serves and the workloads that read it:

```yaml environments/dev/shop/values.yaml
secrets:
  - name: PAYMENTS_API_KEY
    capability: "the payment provider the BFF charges cards through"
    workloads: [bff]
```

Workloads receive their secrets one object per workload. One missing key stops every container in that workload, which is why each secret names its workloads.

## Step 2: Supply the values

Run these from the root of your GitOps repository. You never type the tenant or the cluster: both are read from the app's `values.yaml`.

**One secret at a time:**

```bash
kakt app secrets set dev shop PAYMENTS_API_KEY
```

`set` prompts with echo disabled, or reads `--stdin` so a password manager can pipe into it. No flag takes the value as an argument, so it never reaches your shell history.

**Several at once:**

```bash
kakt app secrets template dev shop > shop.env   # the declared keys, with no values
# fill in shop.env
kakt app secrets import dev shop --from-env shop.env             # lists what it would write
kakt app secrets import dev shop --from-env shop.env --confirm   # writes them
```

`import` writes only the keys the app declares, so anything else in the file is ignored. An entry left empty is never written, so a half-filled file never blanks a secret already supplied.

<Warning>
That file holds your secrets in plaintext. Keep it outside the repository, and delete it once the values are in your box.
</Warning>

## Step 3: Check what is present

```bash
kakt app secrets status dev shop
```

`status` prints key names, never values, so you can paste it into a ticket. Every declared secret is checked before the app's workloads start, and a missing key is reported by name.

<Tip>
You supply each secret once for the life of the box. Rebuilding a cluster does not mean re-entering them: the secret store is backed up and its master keys are in your escrow. To rotate a secret, run `set` again.
</Tip>
