---
title: "Rotate the encryption key"
description: "Two stages: a new write key with the old one kept for reads, then, after every Secret is rewritten, removal of the old one."
keywords: ["rotate key", "kakt encryption rotate", "encryption at rest", "cryptoperiod"]
---

> Nothing is unreadable at any point, as long as you finish in order.

Rotate every 90 days, and at once when a key may have been disclosed. During a rotation the escrow holds both keys, so a cluster that loses its control plane mid-rotation can still be recovered.

## Step 1: Start the rotation

```bash
kakt encryption rotate --box acme-hub --cluster acme-hub --kubeconfig acme-hub.kubeconfig
```

A new key becomes the write key; the current one is kept for reads. Both are escrowed before anything is applied.

## Step 2: Roll the control plane and rewrite every Secret

Wait for the control plane to roll, then rewrite each Secret so it is stored under the new key:

```bash
kakt verify --cluster acme-hub
kubectl get secrets --all-namespaces -o json | kubectl replace -f -
```

## Step 3: Verify

Check that every Secret carries the new key's name, and that the escrowed key decrypts. See [Verify an escrow](/guides/escrow/verify-your-escrow#step-2-check-the-encryption-key-decrypts).

## Step 4: Finish the rotation

```bash
kakt encryption rotate --box acme-hub --cluster acme-hub --finalize
```

It removes the old key, and refuses unless the cluster is actually mid-rotation.

<Warning>
Do not finish until step 3 passes. Anything still sealed under the old key becomes unreadable.
</Warning>
