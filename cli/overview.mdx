> `soloz` is the one tool you run against your box. It scaffolds your GitOps repository, creates your management cluster, supplies your applications' secrets, and reaches your escrow when nothing else can.

## What it is

Every command runs under your own credentials, from your machine or your own CI. The CLI holds no state of its own: it reads your GitOps repository and your clusters, and writes to them. Nothing it does reaches Kamarkat.

The binary carries the platform version it was built for. A box starts on the version the CLI that scaffolded it carried, and moves only through an upgrade proposal you accept.

## Install it

```bash
export SOLOZ_VERSION=<version>
curl -fsSL -o soloz \
  "https://github.com/soloz-io/zero-ops/releases/download/v${SOLOZ_VERSION}/soloz-linux-amd64"
chmod +x soloz && sudo mv soloz /usr/local/bin/
soloz bundle-version
```

## Every command

<Note>
Run `soloz <command> --help` for the complete flag set of any command. This page lists what exists; the pages below document the flags that change what a command does.
</Note>

### Create and declare

| Command | What it does |
| :- | :- |
| `soloz tenant scaffold` | Create your GitOps repository and start Day-0 |
| `soloz tenant add-cluster` | Declare an additional managed cluster |
| `soloz tenant set-gitops-token` | Publish the credential your application builds use |
| `soloz bootstrap-mgmt` | Create the management cluster, as one step rather than a whole box |
| `soloz init-secrets` | Generate the bootstrap secrets the secret store starts from |
| `soloz configure-github-access` | Give the GitOps engine access to your repositories |
| `soloz configure-tailscale` | Supply the auth key nodes on your own premises join with |

<Warning>
`soloz --help` also lists `configure-eso`. It is deprecated and does not belong in any procedure: running it replaces the machine identity your box authenticates with and stops every platform operator. `soloz init-secrets` creates that identity, and nothing else should write it.
</Warning>

### Destroy

| Command | What it does |
| :- | :- |
| `soloz spoke teardown` | Destroy managed clusters, through your provider's API |
| `soloz teardown` | Destroy a whole box: its management cluster, the managed clusters it holds, and their infrastructure |

<Warning>
These delete infrastructure in your cloud account and are not reversible. Both require an explicit confirmation flag.
</Warning>

`soloz teardown` takes the whole box: it reads the managed clusters from the management cluster and removes them with it. `soloz spoke teardown` is for taking managed clusters down on their own, and for the case where the management cluster is already gone and its clusters would otherwise be left running.

Removing an **application** is not a command. Delete its directory under `environments/<env>/<app>/`, regenerate the hostname aggregate with `soloz fleet hosts aggregate`, and commit — your control plane removes what the declaration no longer asks for.

## Conventions these commands share

### Secrets are never arguments

No command takes a secret value as a flag. Values arrive on a prompt with echo disabled, or on stdin so a password manager can pipe into them. A secret passed as an argument sits in your shell history and in the process table for anyone on the machine.

### Four flags recur

| Flag | What it names |
| :- | :- |
| `--cluster` | The cluster the command acts on |
| `--box` | The logical box the escrow is keyed by. It is pinned at scaffold and never changes, so escrow artefacts stay findable across a rebuild |
| `--kubeconfig` | Where to reach the cluster, when it is not where Day-0 put it |
| `--repo` | The root of your GitOps repository, which defaults to the current directory |

Commands that read your applications take `--repo`, and read the tenant and the cell from each application's own `values.yaml` rather than asking you to retype them.

### Dry runs change nothing

`--dry-run` reports what a command would do and writes nothing. Where a command is destructive, it also requires `--confirm`.

### Fingerprints, not values

Commands that inspect secret material print fingerprints. A fingerprint is enough to compare one store against another and useless to anyone who obtains it.
