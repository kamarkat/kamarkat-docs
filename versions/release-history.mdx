## What you need to know

### Upgrade path

Each release states the oldest version it may be taken from, in its release notes. `0.1.15` states `0.1.14`. If your cluster runs an older version than the one stated, upgrade to the stated minimum first.

### Reversibility

No release so far states whether its predecessor can be restored, so each one reads `unknown`. Treat each upgrade as one-way until a release states otherwise.

### Security fixes

No release so far declares security fixes.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Which version should a new box start on?">
    The latest release. Download the `soloz` CLI from that release, and `soloz tenant scaffold` pins your management cluster to it.
  </Accordion>
  <Accordion title="Will an old release ever stop being available?">
    No. Published versions are never deleted. A version leaves its supported window on its stated dates, but it remains available to pull.
  </Accordion>
</AccordionGroup>
