> A short list, and it stays short. Each entry is here because a box cannot be rebuilt without it.

Escrow is an allowlist, not a mirror. Every artifact below answers one question — *is this readable when the management cluster is unavailable, or does not exist yet?* — and anything that answers "it doesn't need to be" is not here.

The second clause admits the credentials a box is **built** with, not just the ones it is
rebuilt from. `kakt box init` enrols them, and the only secrets left on your repository
are the four that say where this escrow is, plus `GITOPS_REPO_WRITE_TOKEN` — which stays
because your own application builds read it from your git organization, and a build
cannot read an escrow.

## Box-scoped

Path: `/boxes/<boxId>`. Permanent, shared by every management cluster the box ever has, because they belong to the box rather than to any cluster in it.

The root is `boxes` because these artifacts are the **box's**, not any component's. Several of them are written before any component of the box is running.

| Artifact | What it protects | Why it must outlive the cluster |
|---|---|---|
| `zitadel-masterkey` | the box's identity provider | without it, a restored identity database is unreadable and nobody can log in to the box they just rebuilt |
| `backup-ssec-key` | the management-state backups | the archive is encrypted with it. Kept outside the box because a key stored in what it protects protects nothing |
| `backup-store-credential` | reaching the backup bucket, and archiving to it | the credential that reaches the backups cannot live in the database those backups restore. One authority, two renderings: `kakt escrow deliver-backup-credentials` writes it as the keys CloudNativePG archives with and the INI Velero restores with |
| `registry-credential` | pulling your own private images | a first bootstrap pulls your images before it has a secret store to read a credential from. The platform's own images are public, so a box without this one still builds |
| `alert-destination` | where this box's alerts page you | the box cannot be the authority for where its own failures are reported: the moment that matters is the moment it is not answering |
| `mail-transport-url` | outbound mail for identity and alerts | the identity provider needs it while it is being created, which is before anything in the box can hold it |
| `tailnet-authkey` | admitting nodes on your own premises | the control plane joins the tailnet during its own first boot, from cloud-init, with no cluster yet to read a Secret from |
| `provider-credential-hetzner` | your cloud account | first bootstrap has no cluster yet, and teardown and inventory must work when the cluster cannot be reached |
| `escrow-destination` | the box's binding to this escrow | records which project this box was established in, so a declaration and its escrow can be checked against each other |

## The secret store and the box's trust

Path: `/openbao`, in the box's escrow project. These belong to the box's secret store and its certificate authority.

| Artifact | What it protects | Why it must outlive the cluster |
|---|---|---|
| `openbao-seal` | the box's secret store | the secret store is sealed with this key, and every generation of it is kept with the history of which was delivered when. A restored database opens only with the key that was in force when it was backed up. Inside the box, that is a circle |
| `openbao-recovery-key-encrypted` | break-glass into the secret store | the recovery key, encrypted to the PGP key in custody. No permanent root token exists, so this is the only way in when everything else fails. The box's automation can read only the ciphertext |
| `openbao-recovery-pgp-public` | encrypting the recovery key | the public half, which Day-0 encrypts the recovery key to |
| `pki-root-certificate` | trusting the box's certificates | the root's public certificate, which `kakt pki sign-intermediate` checks the secret store's chain against |
| `custody-project-id` | finding custody | which project is this box's custody project |

## Custody project

A second project, `<escrow project>-custody`, whose only member is the box's administrator. No automation identity, CI run or cluster can read it. `kakt escrow init` creates it and generates both keys in it.

| Artifact | What it protects | Who reads it |
|---|---|---|
| `pki-root` | the box's root certificate authority, private key included | `kakt pki sign-intermediate`, under your own session, to sign the secret store's intermediate. It never enters CI or a cluster |
| `openbao-recovery-pgp-private` | decrypting the recovery key | you, when you break glass into the secret store |

The issuing intermediate's private key is not escrowed anywhere: it is generated inside the secret store and never leaves it.

## Cluster-incarnation-scoped

Path: `/boxes/<boxId>/clusters/<clusterName>`. Kept for as long as that cluster's recovery point matters, then retired with it.

| Artifact | What it protects | Why it is per cluster |
|---|---|---|
| `admin-kubeconfig` | reaching that cluster's API | it is one cluster's credential; a replacement issues its own, and a shared path would mean the successor overwriting the predecessor's at the moment both are needed |
| `secret-encryption-key` | at-rest encryption in that cluster | the same reason, and a successor's key is its own |
| `secret-encryption-key-previous` | the key before the current one | a rotation leaves data written under the old key; both are needed until re-encryption completes |

## Workload-cluster-scoped

Path: `/boxes/<boxId>/clusters/<cluster>`, under the **workload cluster's** own name — never under whichever management cluster currently manages it. That is what makes management transferable.

| Artifact | What it protects |
|---|---|
| `spoke-pki-ca` | the cluster's certificate authority |
| `spoke-pki-etcd` | its etcd trust root |
| `spoke-pki-sa` | its service-account signing key |
| `spoke-pki-proxy` | its front-proxy authority |

These are the trust roots Cluster API generates for a cluster. They have no source but escrow: the provider's inventory can tell you which server is which machine, and the management-state backup can tell you what that machine's object must contain, but neither holds the cluster's private trust.

## Deliberately not escrowed

<Note>
Most of your secrets are not here, and that is the design. Escrow holds a fixed handful of artifacts whether your box runs one application or forty.
</Note>

| Not escrowed | Where it lives | Why it does not belong in escrow |
|---|---|---|
| Application secrets, API keys, tokens | the box's secret store, delivered as Kubernetes Secrets. The secret store's database is backed up to your object storage | needed only while the box runs. Mirroring them would copy your whole secret estate to a second place for no recovery benefit |
| Application database credentials | the same. The secret store rotates the platform databases' login passwords itself | recreated by their own authority when the application is redeployed |
| The cloud credential the in-cluster controllers use | a Kubernetes Secret the platform maintains | an operational **projection** of the escrowed copy, not a second source |
| Node encryption-key material | file content Cluster API reads at provisioning | a projection of the escrowed key |
| Per-application backup credentials | the operational store | separate from the box's recovery authority on purpose: compromising one must not yield the other |
| Certificate authorities of the **management** cluster | excluded from the management-state backup by label | a restore of them would make the backup tool a second writer of the fleet's trust |

Nothing in this column authenticates to the hosted escrow. No tenant, application or workload cluster holds an escrow credential.

## Checking what is actually there

```bash
kakt escrow verify --box acme-1794447136 --cluster acme-mgmt-1794447136 --management
```

Reports each artifact by fingerprint, never by value. Pass `--management` for a management cluster, where every artifact applies, and `--workload` for a managed cluster, where the management-only artifacts do not — see [`kakt escrow verify`](/cli/escrow-and-encryption#kakt-escrow-verify).
