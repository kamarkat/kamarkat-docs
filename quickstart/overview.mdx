This quickstart takes you from empty accounts to an application served on your own domain. You run every step yourself, under your own credentials. Kamarkat never holds them.

## What you will build

- A **GitOps repository** in your git organization, created and named by `kakt box init`. It is the only source of desired state for your box.
- A **management cluster** that runs the platform's services.
- A **managed cluster** that runs your applications.
- One **application**, deployed from its own repository and served on a hostname under your domain.

## Choose your path

You choose where your nodes run when you create the box, with `--provider`.

| Path | Nodes | Choose it when |
| :- | :- | :- |
| **Cloud** (`hetzner`, default) | Cloud servers in your account | You want the shortest path to a running box |
| **Hybrid** (`hybrid`) | Control plane nodes in the cloud, with worker nodes on your own machines joining over your tailnet | You are building a development box on hardware you already have. Supported for `dev` only. |

This quickstart follows the cloud path. The hybrid path adds a `TS_AUTHKEY` secret and the nodes you list for each managed cluster.

## How it fits together

The quickstart follows the same four phases as [the install journey](/introduction/welcome#from-download-to-running-platform).

<Steps>
  <Step title="Download">
    Prepare a cloud account, a git organization, a domain and an escrow account, and install the `kakt` CLI. See [Prerequisites](/quickstart/prerequisites).
  </Step>
  <Step title="Connect">
    Sign in with `kakt login` and create the escrow project with `kakt escrow init`. `kakt box init` then collects every credential your box is built with. See [Get started](/quickstart/get-started) and [Initialize a box](/quickstart/initialize-a-box).
  </Step>
  <Step title="Initialize">
    `kakt box init` creates your GitOps repository. Declare the management cluster with `kakt tenant add-management`, commit it, and run Day-0 from that repository's own CI. See [Build the management cluster](/quickstart/build-the-management-cluster).
  </Step>
  <Step title="Build">
    Declare a managed cluster with a commit, and the management cluster provisions it. Then declare your application, supply its secrets, and let its build publish and pin its chart. See [Add a managed cluster](/quickstart/add-a-managed-cluster) and [Declare an app](/quickstart/declare-an-app).
  </Step>
</Steps>

## How long it takes

Most of the time goes into Day-0, which creates real infrastructure and runs for a few hours. The steps before and after it take minutes.

<Note>
Creating clusters costs money in your cloud account. Day-0 runs only when you start it, never because a file changed.
</Note>
