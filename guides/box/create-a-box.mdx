> One management cluster per box, built once by Day-0. Everything after it is a commit.

The management cluster runs the platform's services: the GitOps engine, cluster lifecycle, secrets, identity, login and observability. It is the only cluster that needs Day-0. It then creates every managed cluster your repository declares. `kakt box init` declares none: your first managed cluster is a commit you make with `kakt tenant add-cluster`.

You create it once per box. A second box is a second GitOps repository, with its own management cluster.

## Before you start

- **Your accounts and credentials** are ready: see [Prerequisites](/quickstart/prerequisites).
- **Your escrow** exists: see [Get started](/quickstart/get-started). `kakt box init` refuses without it, because an escrow cannot be added afterwards.
- **The provider suits the environment.** `hybrid` is supported for `dev` only.

<Note>
Day-0 creates cloud servers, billed to your account, and runs for a few hours. It runs only when you start it, never because a file changed.
</Note>

## Step 1: Initialize your GitOps repository

```bash
kakt box init \
  --tenant acme \
  --git-org acme-inc \
  --domain acme.example \
  --region hel1
```

<Note>
`--git-org` and the box's own name are different things, and only one of them is yours to pass.

You can usually leave `--git-org` out: it is read from the platform credential when that credential reaches exactly one git organization. Name it when the credential reaches several — the command then refuses and lists them, because a box's repository carries your tenant's name under a timestamped name that cannot be reused, so creating it in the wrong organization is not something the command can undo.

- `--git-org acme-inc` is your **git organization** — where the repository is created.
- The **box's own name is generated**, not passed: one timestamp gives the box id, the repository and the first management cluster's name (`acme-1794447136`, `acme-gitops-1794447136`, `acme-mgmt-1794447136`). The box id is the value `kakt escrow verify --box`, `kakt kubeconfig --box` and the other escrow commands take, and the command prints it when the box is created.

The one human this box accepts for escrow-backed operations is taken from your `kakt login` session and printed as it is used. Pass `--platform-admin` only to name somebody else.
</Note>

Add `--dry-run` first to see the repository without creating anything. Its management cluster is declared separately, with `kakt tenant add-management`. A released CLI starts the box on the version it carries; an unreleased build has none to offer and refuses, so pass `--bundle-version` with a published version. (`development` exists for platform development only: it reads charts from a branch of the platform repository rather than from a published version, so such a box carries no bootstrap workflow and is built locally instead.) Every flag, and the escrow and credential flags a real run needs, are in [Initialize a box](/quickstart/initialize-a-box).

It creates the repository with no clusters and stores your credentials on it as GitHub Actions secrets, which is what the workflow that creates a management cluster runs under — [Where the secrets live](/features/admin/git-connection#where-the-secrets-live). Declare the management cluster next — `kakt tenant add-management`, with no name, which takes the one the box declared — then commit it and dispatch the repository's bootstrap workflow. If the run stops part-way, continue it with `kakt box init --resume <checkout>`, which reuses the identity already written.

## Step 2: Let Day-0 run

Day-0 is the **Bootstrap cluster** workflow in your repository, running on your own CI:

```bash
gh run watch --repo acme-inc/acme-gitops-1794447136
```

It creates the management cluster, builds its foundation, waits for its platform services to become healthy, then brings up any managed cluster your repository already declares. With none declared, it finishes after the management cluster. If a run fails part-way, fix the cause and start it again: completed phases are not repeated. See [Build the management cluster](/quickstart/build-the-management-cluster) for each stage.

## Step 3: Verify

```bash
kakt verify --cluster acme-mgmt-1794447136 --timeout 15m
```

It waits for the management cluster to converge and reports anything outstanding.

## After this

You never run Day-0 again for this box. Every further cluster, environment, app and platform upgrade is a commit to your repository, which the management cluster applies.
