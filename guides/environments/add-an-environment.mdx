> An environment is a directory per app, on a managed cluster that already exists. Declare the cluster first.

This guide adds `stg` to a box that runs `shop` in `dev`. The order matters: an app names the cluster it runs on, and an app naming a cluster that does not exist generates nothing.

## Before you start

**Choose the provider.** `hybrid` is supported for `dev` only. If your `dev` runs on `hybrid`, your `stg` and `prod` run on `hetzner`, so your environments are not all the same provider: the new one has cloud nodes and their cost, and no tailnet. See [Environments](/features/workloads/environments#providers-per-environment).

## Step 1: Declare the cluster

Add a managed cluster for the environment, if it does not have one yet, and wait for it to converge. See [Add a managed cluster](/guides/clusters/add-a-managed-cluster).

Several apps in one environment can share a cluster, so a second app in `stg` needs no second one. Give the cluster `--environment stg`: that is the stage it serves, and the CLI refuses an app whose directory and whose cluster disagree about it.

## Step 2: Declare each app

For each app, declare it in the new environment:

```bash
kakt tenant add-app \
  --env stg \
  --app shop \
  --cluster acme-stg-01 \
  --owner-email platform@acme.example \
  --workload frontend
```

The cluster is checked before anything is written — it must serve `stg`, which is what step 1 declared. Then set what differs from `dev` in `environments/stg/shop/values.yaml`:

```yaml environments/stg/shop/values.yaml
tenantId: acme
appId: shop
clusterName: acme-stg-01 # the cluster you declared in step 1

public:
  hosts:
    - shop.stg.acme.example
```

Declare the same `secrets` as in `dev`: the keys are the same, the values are not.

In each workload's `Chart.yaml`, set the version to promote. See [Promote an app](/guides/apps/promote-an-app).

## Step 3: Supply its secrets

Secrets are supplied per environment. Nothing is copied from `dev`.

```bash
kakt app secrets template stg shop > shop-stg.env   # the declared keys, with no values
# fill in shop-stg.env
kakt app secrets import stg shop --from-env shop-stg.env --confirm
kakt app secrets status stg shop
```

Or one at a time with `kakt app secrets set stg shop <KEY>`. Delete the `.env` file once the values are in your box.

## Step 4: Commit

```bash
git add environments/stg && git commit -m "Add shop to stg" && git push
```

The platform generates the app on its cluster on the next pass. Every declared secret is checked before its workloads start, and a missing key is reported by name.
