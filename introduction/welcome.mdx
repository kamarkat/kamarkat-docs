## Your own enterprise-grade cloud platform. Installed, not assembled.

Kamarkat brings the cloud-native infrastructure and application services your product needs together in one integrated platform. You install it with one CLI, `kakt`, in your own cloud account.

One installer. One tested platform. Your infrastructure, credentials and data remain yours.

Kamarkat is built for startups and engineering teams that want a production-capable cloud foundation without assembling and maintaining an internal platform from scratch.

<Info>
**Where it runs today:** Hetzner Cloud (`hetzner`). A `hybrid` mode, with worker nodes on your own machines, is supported for development boxes only. See [Supported topology](/introduction/architecture#supported-topology).
</Info>

## From download to running platform

<Steps>
  <Step title="Download">
    Get the `kakt` executable for your machine. It carries the platform version your box starts on.
  </Step>
  <Step title="Connect">
    Sign in to your escrow and authorize your cloud and git accounts. `kakt box init` asks for each credential in turn and opens the page that issues it. It keeps what you enter in a local credential store on your machine, and sets the ones your CI needs as encrypted CI secrets on your repository.
  </Step>
  <Step title="Initialize">
    `kakt` creates your GitOps repository and declares your management cluster. Day-0 then builds that cluster from your repository's own CI, and the platform comes up on it.
  </Step>
  <Step title="Build">
    Declare a managed cluster and your applications. Your management cluster provisions the cluster and deploys your apps with their routing, login, database and secrets already wired.
  </Step>
</Steps>

Your GitOps repository contains declarations, not plaintext credentials.

<Note>
`kakt` is the one entry point, but installing is not a single command today. You run a handful of `kakt` commands, commit once, and start the Day-0 workflow, which runs for a few hours. [Get started](/quickstart/overview) walks through every step.
</Note>

| You provide | The platform supplies |
| :- | :- |
| A cloud account, and the authorization to build in it | Infrastructure provisioning and cluster lifecycle |
| A git organization, and the authorization to write to it | The GitOps foundation every change goes through |
| A domain, and the configuration only you can choose | Networking, DNS, certificates and the gateway |
| Your application code and your business data | Standardized delivery, and the capabilities you select |
| Your operational and release decisions | Versioned platform components, pre-flight checks on upgrades, and the `kakt` CLI |

## Why Kamarkat

| | Hosted platform | Assembling it yourself | Kamarkat |
| :- | :- | :- | :- |
| **Where it runs** | The vendor's infrastructure | Your cloud account | Your cloud account |
| **Who holds the credentials** | The vendor | You | You |
| **Integration work** | Done by the vendor | Yours, per component | Done before you install |
| **How changes arrive** | The vendor applies them | You track each component | One tested version, proposed to your repository for you to merge |
| **What it is built from** | The vendor's stack | Whatever you choose | Open-source components you can inspect |
| **How you set it up** | Sign up | Many tools, each configured by hand | One CLI |

## What arrives integrated

| | |
|---|---|
| **Cluster lifecycle** | Declare a cluster and the platform provisions it, brings up its networking, storage and delivery, registers it, scales it and removes it |
| **GitOps delivery** | Your repository is the desired state; platform controllers reconcile to it |
| **Databases** | A database per application, with credentials, backups and recovery procedures. *Selectable, on by default* |
| **Identity** | An identity provider in your box, and a gateway that fronts your applications with login |
| **Secrets** | A secret store, delivery into workloads, and recovery material held outside the box |
| **Networking, DNS, certificates** | Gateway routing, network policy, DNS records, certificates issued and renewed |
| **Observability** | Metrics, logs, dashboards and alert routing across the box. *Selectable, on by default* |
| **Agentic operations** | *In development.* Platform agents, a registry of the tools they may use, and reusable skills that carry the platform's own conventions |

Packaging these would be a distribution. **Pre-integrating them is the product:** the gateway knows about your identity provider, an application's chart gets its database and its secrets, a new cluster arrives with its networking and delivery already configured, and one version moves them together.

## The platform at a glance

Architecturally, Kamarkat is a platform OS: three layers of one product, not three things to buy.

```text
┌─ Agentic operations (in development) ─────────────────────────────────┐
│  Agents · MCP registry · Skills registry                              │
│  How engineers and AI agents inspect, investigate and operate         │
└───────────────────────────────────────────────────────────────────────┘
┌─ Integrated cloud-native platform OS ─────────────────────────────────┐
│  GitOps · Identity · Secrets · Databases · Gateway · Networking       │
│  Observability · Application delivery · Cluster lifecycle             │
│  Versioned together, reconciled from your repository                  │
└───────────────────────────────────────────────────────────────────────┘
┌─ Business-owned infrastructure ───────────────────────────────────────┐
│  Management cluster · Managed clusters · Cloud infrastructure         │
│  Storage · Networking                                                 │
└───────────────────────────────────────────────────────────────────────┘
```

The agentic layer is designed not to sit beside the platform with its own view of the world. Agents are to read the same platform state engineers do, and change desired state through the same declarative contracts the platform reconciles. [How Kamarkat works](/introduction/approach#one-agentic-operating-experience) describes the design.
