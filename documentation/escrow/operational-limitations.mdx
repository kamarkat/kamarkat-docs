> Six operating details worth knowing before you rely on this. Each one shapes how you run the box day to day.

## Escrow permissions cannot be scoped below the project

Infisical's free plan offers built-in roles only. Custom roles and **folder-level access controls are paid features**, so a member cannot be restricted to one box's subtree of an escrow project.

**What this means for you:** the unit of isolation is the project. Use one escrow project per box, and keep each project's human membership to the one declared administrator. A member of a project can read every artifact in it.

## Five identities, humans included

The free plan allows **five identities per organization, human and machine combined**. A person who logs in consumes one exactly as a machine identity does.

**What this means for you:** nothing in the platform creates an identity — none per box, cluster, tenant, application or login — so the count does not grow with your estate. But every engineer who logs in costs a slot, which is the practical argument for one declared administrator. A machine identity granted several projects has access across those boxes; that is the cost of staying inside five, and it is worth deciding consciously rather than discovering.

## `kakt logout` does not revoke anything server-side

```bash
kakt logout
```

See [`kakt logout`](/cli/signing-in).

Deletes the session from your operating system's credential store. It does not call Infisical, because there is no revocation endpoint this CLI can use.

**What this means for you:** a lost or compromised workstation is remediated **in Infisical** — revoke the session or remove the identity there — not with `kakt logout`. Treat logout as tidying your own machine.

The same applies to your automation credential, with one detail worth knowing: deleting a credential or an identity takes effect immediately, while revoking an access token on its own can leave it usable for up to **12 minutes** if Infisical's cache is briefly unavailable. When a leak matters, delete rather than revoke. [Operating the machine identity](/documentation/escrow/platform-administrator#operating-the-machine-identity) covers the rotation that has to follow.

## A wrong machine-identity secret locks the identity

Infisical blocks an auth method after three failed logins within 30 seconds, for five minutes. That default applies whether or not you configured it.

**What this means for you:** a mistyped `INFISICAL_ESCROW_CLIENT_SECRET` in CI does not simply fail — the retry fails too, and the run reads like an escrow outage rather than a bad credential. Check the value before concluding anything is wrong with the escrow, and expect a five-minute wait after fixing it.

Related: the platform sets no client-secret TTL and assumes none, so if you give that secret an expiry, add a Credential Expiration alert with it — nothing in the platform warns you as the date approaches. See [Operating the machine identity](/documentation/escrow/platform-administrator#operating-the-machine-identity).

## Branch protection is yours to set

Two safety properties depend on the repository that carries your declarations being governed: the escrow coordinates that say where recovery material is written, and the workload-cluster removal check that gates destructive commits.

The platform cannot enforce this from inside. A required status check protects nothing if a commit can reach `main` another way.

**What this means for you:** enable branch protection on `main` — required review, the removal check required, no force-push and no bypass. Without it, the escrow destination and the removal gate are both advisory.

## Two workstations can race one bootstrap

A bootstrap dispatched through your repository's workflow is serialized per box, so two overlapping dispatches cannot both proceed. Two operators running `kakt bootstrap` from their own machines are outside that mechanism.

**What this means for you:** admission narrows the window to the time between reading the provider inventory and creating the first resource, but it cannot close it. Build boxes through the workflow, which is the supported path.
