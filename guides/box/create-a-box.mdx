> One management cluster per box, built once by Day-0. Everything after it is a commit.

The management cluster runs the platform's services: the GitOps engine, cluster lifecycle, secrets, identity, login and observability. It is the only cluster that needs Day-0. It then creates every managed cluster your repository declares. Scaffolding declares none: your first managed cluster is a commit you make with `kakt tenant add-cluster`.

You create it once per box. A second box is a second GitOps repository, with its own management cluster.

## Before you start

- **Your accounts and credentials** are ready: see [Prerequisites](/quickstart/prerequisites).
- **Your escrow** exists: see [Get started](/quickstart/get-started). Scaffolding refuses without it, because an escrow cannot be added afterwards.
- **The provider suits the environment.** `hybrid` is supported for `dev` only.

<Note>
Day-0 creates cloud servers, billed to your account, and runs for a few hours. It runs only when you start it, never because a file changed.
</Note>

## Step 1: Scaffold your GitOps repository

```bash
kakt box init \
  --tenant acme \
  --box acme-inc \
  --domain acme.example \
  --region hel1
```

<Note>
Two values are easy to mix up, because `--box` means something different here than it does on the escrow commands.

- `--box acme-inc` is your **git organization** — where the repository is created, as `github.com/acme-inc/acme-gitops`.
- The **box's own name** is `--box-id`, which defaults to the management cluster's name (`acme-hub`). That is the value `kakt escrow verify --box`, `kakt kubeconfig --box` and the other escrow commands take.

The one human this box accepts for escrow-backed operations is taken from your `kakt login` session and printed as it is used. Pass `--platform-admin` only to name somebody else.
</Note>

Add `--dry-run` first to see the repository without creating anything. The box's identity is `<tenant>-hub` unless you pass `--box-id`, and its management cluster is declared separately with `kakt tenant add-management`. A released CLI starts the box on the version it carries; an unreleased build has none to offer and refuses, so pass `--bundle-version` with a published version, or `development` to read charts from your current branch. Every flag, and the escrow and credential flags a real run needs, are in [Create your box](/quickstart/create-your-box).

It creates the repository with no clusters and stores your credentials on it as secrets. Declare the management cluster next, with `kakt tenant add-management --name <cluster>`, then commit it and dispatch the repository's bootstrap workflow.

## Step 2: Let Day-0 run

Day-0 is the **Bootstrap cluster** workflow in your repository, running on your own CI:

```bash
gh run watch --repo acme-inc/acme-gitops
```

It creates the management cluster, builds its foundation, waits for its platform services to become healthy, then brings up any managed cluster your repository already declares. With none declared, it finishes after the management cluster. If a run fails part-way, fix the cause and start it again: completed phases are not repeated. See [Bootstrap your box](/quickstart/bootstrap-your-box) for each stage.

## Step 3: Verify

```bash
kakt verify --cluster acme-hub --timeout 15m
```

It waits for the management cluster to converge and reports anything outstanding.

## After this

You never run Day-0 again for this box. Every further cluster, environment, app and platform upgrade is a commit to your repository, which the management cluster applies.
