> Day-0 builds a management cluster. A managed cluster is a commit.

Day-0 runs once, to build your box's management cluster. Every managed cluster after that is a declaration in your GitOps repository: you commit it, and the management cluster provisions it. You never run Day-0 again to add one.

## Before you start

- **Choose the name.** It becomes the cluster's cell id for its whole life. Applications name the cell they run on, so a rename is not an edit: it is a new cluster. A retired name cannot be reused (see [Retire an environment](/guides/retire-an-environment)).
- **Choose the version.** `--bundle-version` must name a platform version that is already published, in the registry your `bundle.yaml` files pull from, and pullable without credentials. The new cluster cannot converge on a version its registry does not hold. Use the version your other clusters run unless you mean to differ.
- **Check the provider supports the environment.** `hybrid` is supported for `dev` only. A `stg` or `prod` cluster runs on `hetzner`. See [Environments](/features/workloads/environments#providers-per-environment).

## Step 1: Declare the cluster

From the root of your GitOps repository:

```bash
kakt tenant add-cluster \
  --mgmt-cluster acme-hub \
  --name acme-stg-01 \
  --environment stg \
  --tenant acme \
  --bundle-version <version> \
  --gitops-repo-url https://github.com/acme-inc/acme-gitops
```

It writes `registry/clusters/acme-stg-01/`, the platform this cluster runs, and `registry/clusters/acme-hub/acme-stg-01-infrastructure.yaml`, the Application on the management cluster that creates it. It refuses a name that is already declared.

<Note>
A managed cluster is a new set of nodes in your cloud account, billed like any other. On `hetzner` it starts with 2 worker nodes unless you pass `--workers`. A `hybrid` cluster buys no cloud workers: it runs on the machines you list in `registry/clusters/<name>/infrastructure/spokepool-hybrid.yaml`, and has no capacity until you list them.
</Note>

## Step 2: Commit

```bash
git add registry && git commit -m "Declare acme-stg-01" && git push
```

The management cluster provisions the cluster from this commit, then installs the platform on it at the version you named.

## Step 3: Verify

```bash
kakt verify --cluster acme-stg-01
```

It waits for the cluster to converge and reports what is outstanding. It reads the cluster's kubeconfig from `k8-secrets/kubeconfig/acme-stg-01.kubeconfig`; pass `--kubeconfig` to point elsewhere.
