> For when sign-in is not available. Not for everyday access.

Normal access is through your box's identity provider, where each person signs in as themselves. The admin kubeconfig in your escrow is for when that is not possible: the identity provider is down, the cluster is broken, or nobody can sign in.

## Step 1: Retrieve it

Run it from your box's GitOps repository:

```bash
kakt kubeconfig --cluster acme-hub --gitops-dir . --out acme-hub.kubeconfig
```

The repository declares which escrow holds the box, and the read is performed with your own [`kakt login`](/cli/signing-in) session — attributed to you in the escrow's audit log, and authorized by your access to the escrow project rather than by a shared credential on your machine.

Without a checkout, pass `--box acme-hub` and the four `INFISICAL_ESCROW_*` values in the environment instead. That is the automation path.

The escrow holds one kubeconfig per cluster. Pass the cluster you need.

## Step 2: Use it

```bash
kubectl --kubeconfig acme-hub.kubeconfig get nodes
```

## Step 3: Discard it

```bash
rm acme-hub.kubeconfig
```

<Warning>
The credential is cluster-admin and is not tied to a person. Never commit it, and never keep it after the emergency.
</Warning>
