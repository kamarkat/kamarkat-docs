> Your clusters are created in your cloud account, with your token. Kamarkat never receives it.

## What it is

The cloud account is where your management cluster and managed clusters run, and what your cloud provider bills you for. Its API token is stored as the `HCLOUD_TOKEN` secret on your GitOps repository, where Day-0 reads it, and then held by your management cluster, which creates every later cluster with it.

| Provider | What it runs |
| :- | :- |
| `hetzner` | Clusters on cloud servers. The default. |
| `hybrid` | Control plane nodes in the cloud, with worker nodes on your own machines joining over your tailnet. Supported for `dev` only. |

## Getting started

### 1. Create a project and an API token

Create a project in your cloud console for this box, then create an API token in it with read and write permission.

### 2. Host your domain's DNS zone with the provider

Your box creates DNS records and proves domain ownership for its certificates through your provider's DNS service, so your domain's zone must be hosted there.

### 3. Store the token on your GitOps repository

`kakt box init` stores it for you, prompting with echo disabled if you did not export it. To set it yourself:

```bash
gh secret set HCLOUD_TOKEN --repo acme-inc/acme-gitops
```

## What you need to know

### Region and size

You choose the region when you create the box (`--region`) and when you add a managed cluster. A managed cluster starts with 2 cloud worker nodes unless you pass `--workers`.

### Nodes on your own machines

`hybrid` is a development provider. Its platform database uses node-local storage, so `stg` and `prod` run on `hetzner` only. With `hybrid`, a managed cluster has no cloud workers: its capacity is the hardware you list for it. Until you add nodes, workloads stay pending. The control plane and those nodes join your tailnet with the `TS_AUTHKEY` secret.

### One account per box

A box's clusters all run in one cloud account, and no component in one box holds a credential for another.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can I rotate the cloud token?">
    Yes. Create a new token in your cloud console, set it on your GitOps repository, then revoke the old one.
  </Accordion>
  <Accordion title="Does Kamarkat ever see my bill or my token?">
    No. The token lives only in your repository's secrets and your management cluster, and the bill is between you and your provider.
  </Accordion>
</AccordionGroup>
