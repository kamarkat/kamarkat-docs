> Kamarkat provides the capability. You own the use you make of it.

## What it is

A capability is something the platform provides that contains none of your own logic: a database engine, an identity provider, a gateway, a certificate authority, a metrics store. The schemas in the database, the users in the identity provider and the routes through the gateway are yours.

Capabilities come in two kinds.

**Machinery** runs on every box, because without it a box cannot reconcile anything. You cannot turn it off.

**Selectable capabilities** are ones you choose in your cluster's values. A box runs what you need and does not carry the rest.

Selecting a capability does not change what it is: every capability, selected or not, ships with the bundle, moves with each version, and was tested on the same machinery.

## What you need to know

### Capabilities have a lifecycle

A capability moves through **declared**, **supported**, **deprecated** (still shipped, with an end date), **end-of-life** and **removed**. A capability is never removed from a running box. Before end-of-life you receive notice and, where one exists, a migration path.

### Selecting is set up at provisioning

Turning a capability off in your values stops new clusters getting it. On a box that already runs it, the capability keeps running: removing platform state is never a side effect of changing a value.

### Each capability is tested on the machinery

A bundle version certifies the machinery as a unit and each capability against it. Capabilities that genuinely interact are certified as a named pair.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="How do I add a tool my apps need, such as a database?">
    It is already in your box. Every capability ships with each version; databases and observability are on by default. To turn one on or off, change its value in your cluster's `values.yaml` and commit:

    ```yaml
    capabilities:
      database:
        enabled: true
    ```

    There is nothing to browse, install or register. A capability you leave off still moves with each version, so turning it on later is the same one-line change.
  </Accordion>
  <Accordion title="Can I bring my own database or identity provider?">
    The platform's own components authenticate against the box's identity provider, so it is machinery. Your applications can call any external service you declare.
  </Accordion>
</AccordionGroup>
